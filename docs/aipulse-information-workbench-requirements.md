# AIpulse 信息工作台需求文档

> 范围：基于当前 `Python pipeline + Astro static site` 架构，对 AIpulse 的前端产品形态做下一阶段演进。
> 目标：把 AIpulse 从“静态日报展示页”提升为“有编辑判断的 AI 资讯工作台”。

## 1. 背景

当前 AIpulse 已经具备：

- Python 抓取、打分、筛选、生成 `data/*.json`
- Astro 静态站渲染首页、归档页、分类页
- Product Hunt / 官方博客 / arXiv / HuggingFace 等多类数据源

当前主要问题：

- 首页仍偏“展示页”，扫读效率不够高
- 分类页缺少真正的高密度资讯流体验
- 缺少“全部动态”页承接高频浏览
- 前端对后端已有的评分理由、信号字段利用不足
- 稀疏日和富内容日使用了过于相似的页面节奏

## 2. 产品定位

AIpulse 不是：

- AI 官网
- 营销 landing page
- 通用博客

AIpulse 是：

- 面向中文 AI 从业者的每日资讯工作台
- 强调筛选、排序、理由和来源信号
- 适合每天多次打开、快速扫读和回看

## 3. 目标用户

核心用户：

- 模型应用开发者
- AI 产品经理
- Agent / LLM 工程师
- 关注模型、产品、行业和论文动态的从业者

核心使用场景：

- 早上快速扫一遍当天重点
- 白天按分类深挖某一赛道
- 回看前几天某条更新或论文

## 4. 产品目标

### 4.1 主页目标

- 用最短路径告诉用户“今天最值得看什么”
- 快速暴露分类入口
- 减少重复内容和过大的视觉空转

### 4.2 分类页目标

- 成为高频使用的专题信息流页面
- 强化来源、时间、分数、理由、信号标签
- 让用户能快速按来源扫读

### 4.3 全部动态页目标

- 承接“今天所有入选内容直接刷”的需求
- 成为最像信息终端的页面
- 提供按分类、来源、排序的高效浏览能力

### 4.4 归档目标

- 让用户可以低成本回看某天内容
- 先从最近几期切入，再进入单日完整页

## 5. 功能需求

## 5.1 首页

必须具备：

- 今日日期、生成时间、总条数、版块数
- 收敛后的头条区
- 分类入口前置
- 分类精选列表
- 与头条区去重
- 稀疏日提示

不应继续保留：

- 过强的“营销式 hero”
- 大面积解释性文案
- 同一批内容重复出现两次以上

## 5.2 分类页

必须具备：

- 动态显示真实聚合窗口
- 高密度信息流
- 来源分组
- 来源跳转
- 每条资讯的理由/信号表达

## 5.3 全部动态页

新增页面：

- 建议路径：`/latest` 或 `/all`

必须具备：

- 全量最近聚合内容列表
- 分类筛选
- 来源筛选
- 排序方式切换（时间 / rankingScore）

## 5.4 卡片

必须展示：

- 标题
- 来源
- 发布时间
- 分类
- 分数
- 原文链接

应优先展示：

- 推荐理由 `score_details.reason`
- Product Hunt 票数 / featured
- 来源信号（官方 / 论文 / 产品榜）

## 5.5 空态与稀疏态

必须区分：

- 完全无内容
- 某分类无内容
- 当日内容很少但不为空

## 6. 内容策略要求

页面不追求“像实时 AI 热榜”，而是强调：

- 这是日报产品
- 有筛选和编辑判断
- 有明确的来源边界

不应误导用户：

- 不把测试数据当生产数据展示
- 不用 UI 暗示自己覆盖了并不存在的实时信号源

## 7. 设计原则

- 浅色主界面，工具型而非营销型
- 以信息结构优先，不靠深色和发光营造“AI 感”
- 首页偏日报目录
- 列表页偏情报流
- 高密度但不压抑

## 8. 非目标

本阶段不做：

- 运行时 API 驱动前端
- 用户登录、收藏、订阅系统
- 搜索引擎式全文检索
- 实时分钟级刷新
- 拆分前后端仓库

## 9. 成功标准

这轮优化完成后，应达到：

- 首页 5 秒内能扫清“今天重点”
- 分类页适合连续浏览，不像博客列表
- 新增“全部动态”页后，重度用户不必依赖首页反复跳转
- 前端能表达“为什么这条值得看”
- 部署内容只使用生产数据，不再混入 demo 产物
