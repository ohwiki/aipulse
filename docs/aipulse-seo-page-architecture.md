# AIpulse 页面信息架构与 SEO 页面清单

更新时间：2026-05-09

## 目的

本文档用于约束 `AIpulse` 后续页面建设，确保每个页面都具备明确职责、独立价值和可索引性。

后续大模型在新增页面、改页面结构、补 SEO 字段时，应优先参考本文档。

## 总体原则

### 1. 页面必须有独立职责

不要为了“页面数量”而新增页面。  
每个页面都必须先回答：

1. 这个页面解决什么用户问题
2. 这个页面和首页/分类页/归档页有什么区别
3. 这个页面是否具备独立搜索价值

### 2. 页面必须形成站内内容网络

`AIpulse` 不是单页产品，而是内容网络。

页面之间应始终保持清晰跳转：

- 首页 -> 分类页 / 归档页 / 单日页 / About
- 分类页 -> 其他分类页 / 首页 / 原文
- 归档页 -> 单日页
- 单日页 -> 上一日 / 下一日 / 归档页 / 首页
- About / 信任页 -> 首页

### 3. 页面内容不能只是换壳重复

如果新页面和已有页面只是：

- 展示同一批内容
- 只换标题
- 只改一点点排序

那就不应新增。

## 当前核心页面

### 1. 首页 `/`

#### 页面职责

- 让用户最快理解“今天 AI 圈最重要的事”
- 承接品牌第一印象
- 承担主入口作用

#### 页面价值

- 今日精选
- 主头条
- 分类入口
- 当天重点总览

#### SEO 方向

- 适合承接品牌词、泛词、站点首页权重
- 不应承担所有长尾流量期待

#### 页面要求

- 首屏高信息密度
- 强主头条
- 明确“今日为何值得看”
- 清晰通向分类页和归档页

#### title / description 建议

- `title`: `AIpulse | 今日 AI 资讯精选`
- `description`: `面向中文 AI 从业者的每日资讯精选，快速查看今天最值得关注的模型、产品、行业与研究动态。`

### 2. 归档页 `/archive`

#### 页面职责

- 帮助用户回看历史日报
- 帮助用户快速定位特定日期

#### 页面价值

- 日期索引
- 每日摘要卡
- 回看路径

#### SEO 方向

- 承接与“日报归档”“历史 AI 日报”相关的页面价值
- 更重要的是帮助搜索引擎理解站内日期内容结构

#### 页面要求

- 不是纯日期列表
- 每个日期卡都要能表现“当天重点”
- 点进去前用户就能判断是否值得看

#### title / description 建议

- `title`: `AIpulse | 日报归档`
- `description`: `按日期查看 AIpulse 的历史日报，快速回看每天的重要 AI 动态与精选条目。`

### 3. 单日页 `/archive/{date}`

#### 页面职责

- 承接某一天的完整日报内容
- 作为“可分享的单日记录页”

#### 页面价值

- 完整当日结构化摘要
- 分类组织
- 相邻日期连续浏览

#### SEO 方向

- 更适合承接具体日期型查询
- 有机会承接带日期的长尾流量

#### 页面要求

- 明确日期、条数、版块数、生成时间
- 内容按分类组织
- 支持上一日 / 下一日浏览

#### title / description 建议

- `title`: `AIpulse | 2026-05-09 AI 日报`
- `description`: `查看 2026-05-09 的 AIpulse 日报，按分类回看当天值得关注的 AI 模型、产品、行业和研究动态。`

### 4. 分类页 `/category/{slug}`

#### 页面职责

- 承接明确主题下的连续内容流
- 成为长期 SEO 的主力入口之一

#### 页面价值

- 主题沉淀
- 最近一段时间的连续更新
- 同类内容快速扫读

#### SEO 方向

- 最适合承接主题型长尾词
- 后续可成为自然流量的重要来源

#### 页面要求

- 正文流比导航更重要
- 要有该主题的积累感
- 不能只是首页精选换个标题

#### title / description 模板

- `title`: `AIpulse | {分类名称}`
- `description`: `查看最近 7 天的 {分类名称} 条目，快速掌握该主题下值得关注的 AI 动态。`

### 5. About 页 `/about`

#### 页面职责

- 解释站点定位
- 增强用户信任
- 帮助搜索引擎理解站点是什么

#### 页面价值

- 站点定位说明
- 数据来源说明
- 更新节奏说明
- 内容归属说明

#### SEO 方向

- 不一定承担流量主入口作用
- 但对站点整体信任和收录理解很重要

#### title / description 建议

- `title`: `AIpulse | 关于`
- `description`: `了解 AIpulse 的定位、数据来源、更新方式，以及站点如何进行 AI 资讯聚合与摘要整理。`

## 后续必须补齐的页面

### 1. Privacy Policy `/privacy`

#### 页面职责

- 说明站点如何处理访问数据、统计信息、第三方脚本与广告

#### 为什么必须有

- 未来接广告时几乎是基础要求
- 对用户信任和合规也有帮助

### 2. 联系方式页 `/contact`

#### 页面职责

- 提供反馈、纠错、合作或内容线索提交入口

#### 为什么必须有

- 增强站点可信度
- 为后续商务/合作/侵权处理提供正式入口

### 3. 方法说明页 `/methodology`

#### 页面职责

- 说明 AIpulse 如何抓取、筛选、排序和生成摘要

#### 为什么必须有

- 这是 `AIpulse` 与普通搬运站之间最重要的差异化说明之一
- 对用户、搜索和广告审核都有帮助

### 4. 内容来源与版权页 `/sources-and-attribution`

#### 页面职责

- 说明来源范围、引用方式、版权边界和跳转原则

#### 为什么必须有

- 降低“采集站”观感
- 强化“聚合 + 摘要 + 导航”定位

## 页面建设优先级

### 第一优先级

1. 首页继续优化
2. 归档页继续优化
3. 分类页继续优化

### 第二优先级

1. Privacy Policy
2. 联系方式页
3. 方法说明页
4. 来源与版权页

### 第三优先级

1. SEO 细化
2. 站内内链增强
3. 结构化数据与分享信息增强

## 页面元信息要求

后续所有页面默认应检查以下项目：

1. `title` 是否独立且准确
2. `description` 是否体现该页独立价值
3. `canonical` 是否正确
4. 页面是否有明确 `h1`
5. 页面是否有足够的站内返回路径

## 后续模型执行规则

后续任何大模型在为 `AIpulse` 增加页面或改页面时，应默认遵守：

1. 先定义页面职责，再实现页面
2. 先说明页面独立价值，再新增页面
3. 优先复用现有布局与组件
4. 不要制造重复页
5. 不要把页面做成营销页或空洞说明页
6. 所有页面都应有助于搜索、阅读和未来广告变现基础

## 总结

`AIpulse` 的页面建设目标，不是把页面越做越多，而是把每一类页面都做成“有独立价值、可索引、可持续扩展”的内容节点。
