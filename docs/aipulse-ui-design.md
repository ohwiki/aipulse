# AIpulse UI 设计规范

> 面向大模型实现的前端 UI 规格文档。
> 目标不是描述“设计感觉”，而是提供一份足够明确、可以直接落代码的页面与组件约束。

## 1. 文档目标

这份文档用于指导大模型实现 AIpulse 前端 UI。

因此文档必须满足以下要求：

- 明确页面结构，而不是只描述概念
- 明确组件职责，而不是只给组件名字
- 明确字段显示规则，而不是让实现时自由发挥
- 明确视觉 token、间距、字号、边框和布局约束
- 明确不要做什么，避免大模型引入营销页、博客页或过度装饰

## 2. 产品形态定义

AIpulse 是一个 **每日 AI 资讯简报站点**，不是博客，不是 SaaS 控制台，也不是品牌营销页。

UI 目标：

- 打开首页后立即看到“今天最重要的 AI 资讯”
- 允许用户按日期回看日报
- 允许用户按分类连续浏览近期条目
- 保持高可读性、高扫描效率、低视觉噪音

禁止偏离到以下形态：

- 大型 hero marketing 页面
- 博客封面图 + 正文详情页模式
- 仪表盘式多图表界面
- 装饰性卡片堆叠
- 夸张渐变、光效、插画背景

## 3. 页面清单

必须实现以下页面：

1. `/` 首页
2. `/archive` 归档页
3. `/archive/{date}` 单日日报页
4. `/category/{slug}` 分类页
5. `/about` 关于页

## 4. 全局布局规则

### 4.1 页面宽度

- 页面内容最大宽度：`1120px`
- 页面左右内边距：
  - 手机：`16px`
  - 平板：`24px`
  - 桌面：`32px`

### 4.2 垂直节奏

- 页面主区块之间的垂直间距：
  - 手机：`40px`
  - 桌面：`56px`
- 区块标题与内容之间间距：`16px`
- 卡片内部垂直间距：`8px` 或 `12px`

### 4.3 栅格

- 手机：单列
- 平板：单列为主，首页头条区可做 `1 + 2` 结构
- 桌面：
  - 首页头条区允许双栏
  - 其他内容保持纵向阅读优先
  - 不做 masonry，不做三列新闻墙

## 5. 视觉 Token

以下 token 必须固定，避免大模型自由发挥成别的风格。

### 5.1 颜色

```text
--bg: #fcfcfd
--surface: #ffffff
--surface-muted: #f5f5f7
--text: #111114
--text-muted: #5b5b66
--text-soft: #7a7a85
--border: #e7e7ec
--border-strong: #d8d8e0
--accent: #6d4aff
--accent-soft: #f1edff
--accent-text: #4b2fd6
--success: #0f9f6e
--warning: #b7791f
```

### 5.2 字号层级

```text
--font-xs: 12px
--font-sm: 14px
--font-md: 16px
--font-lg: 18px
--font-xl: 24px
--font-2xl: 32px
```

### 5.3 行高

```text
--leading-tight: 1.3
--leading-normal: 1.6
--leading-relaxed: 1.75
```

### 5.4 圆角

```text
--radius-sm: 6px
--radius-md: 8px
--radius-lg: 10px
```

限制：

- 不允许大圆角卡片风格
- 不允许胶囊形大按钮泛滥
- 普通信息卡片圆角上限 `8px`

### 5.5 阴影

默认不用重阴影。

仅允许极轻微阴影：

```text
0 1px 2px rgba(16, 24, 40, 0.04)
```

更推荐使用边框和背景层次，而不是阴影堆叠。

## 6. 导航与全局框架

### 6.1 顶部导航 `HeaderBar`

必须包含：

- 左侧品牌名：`AIpulse`
- 右侧导航：`今日`、`归档`、`分类`、`关于`

桌面端：

- 横向导航
- 当前页面高亮

移动端：

- 仍优先保持简洁的顶栏
- 如果空间不足，可折叠成轻量菜单
- 不要做全屏抽屉式复杂导航

### 6.2 页脚

必须包含：

- 更新时间说明
- 数据来源说明
- 原文归属免责声明

不要在页脚塞大量链接和品牌介绍。

## 7. 首页 `/`

## 7.1 页面目标

首页必须让用户在 5 秒内完成两件事：

1. 知道今天有哪些重要 AI 资讯
2. 知道可以从哪里看更多历史内容

## 7.2 首页结构

按以下顺序固定实现：

1. 顶部信息区
2. 今日头条区
3. 分类精选区
4. 历史日报入口区
5. 页脚说明区

## 7.3 顶部信息区

显示字段：

- 页面标题：`今日 AI 资讯精选`
- 副信息：日期 + 生成时间
- 一个跳转按钮：`查看历史日报`

约束：

- 不要放大 banner
- 不要放产品长介绍
- 首屏必须保留一部分实际资讯内容

## 7.4 今日头条区 `DailyHero`

数据：

- 当天总分最高的 3-5 条资讯

桌面布局：

- 左侧 1 条主头条
- 右侧 2-4 条次级头条纵向排布

手机布局：

- 顺序纵向堆叠
- 第一条仍需视觉更强

主头条必须显示：

- 标题
- 来源
- 发布时间
- 分数
- 摘要
- 原文链接

次级头条可简化，但仍必须至少显示：

- 标题
- 来源
- 分数
- 链接

## 7.5 分类精选区 `SectionBlock`

每个分类单独一个 section，顺序固定：

1. `ai-models`
2. `ai-products`
3. `industry`
4. `paper`
5. `tip`

如果某个分类当天没有数据：

- 默认不渲染空 section

每个 section 显示：

- 分类名称
- 一句话分类说明
- 该分类条目列表

每个 section 默认显示 `3-8` 条。

## 7.6 历史日报入口区

这是一个简单的信息入口区，不是 CTA 广告区。

显示内容：

- 一句说明：可查看最近历史日报
- 一个按钮：进入归档页

## 8. 归档页 `/archive`

## 8.1 页面目标

让用户快速定位某一天的日报，而不是在这里读完整内容。

## 8.2 列表结构

每一天使用一个 `ArchiveDayCard`。

每张卡片显示：

- 日期
- 当日总条数
- 分类数量
- 代表性标题 2-3 条
- 跳转按钮或整卡可点击

卡片布局：

- 单列垂直排列
- 卡片高度由内容决定
- 不能为了“好看”做成多列密集画廊

## 9. 单日日报页 `/archive/{date}`

## 9.1 页面目标

完整呈现某一天的日报内容。

## 9.2 页面结构

顺序固定：

1. 返回归档入口
2. 页面标题（日期）
3. 日期统计信息
4. 各分类 section
5. 前后一天导航

## 9.3 前后导航

如果存在上一天或下一天：

- 提供明确文本链接
- 文案直接写日期，不用只放箭头图标

## 10. 分类页 `/category/{slug}`

## 10.1 页面目标

查看最近 7 天某一分类的连续资讯流。

## 10.2 页面结构

1. 分类标题
2. 分类说明
3. 最近 7 天条目列表

列表排序：

- 先按 `publishedAt` 倒序
- 时间相同时按 `score` 倒序

## 11. 关于页 `/about`

内容应简洁，只包括：

- AIpulse 是什么
- 数据从哪里来
- 多久更新一次
- 原文版权归原始来源所有

不要把关于页写成品牌宣传页。

## 12. 核心组件规范

## 12.1 `NewsCard`

这是最关键组件，必须统一。

### 显示字段

完整模式 `full` 必须显示：

- 中文标题
- 英文标题（如有，可选显示）
- 来源
- 发布时间
- 分类标签
- 分数
- 中文摘要
- 原文链接

紧凑模式 `compact` 必须显示：

- 标题
- 来源
- 发布时间或分数
- 原文链接

### 布局规则

- 标题始终在最上方
- 元信息单独一行
- 摘要在标题之后
- 操作链接在底部

### 视觉规则

- 卡片背景：`--surface`
- 边框：`1px solid var(--border)`
- 圆角：`--radius-md`
- 内边距：
  - 手机：`16px`
  - 桌面：`18px`

### 分数字段

分数以小型强调标签显示，如 `9.1`

约束：

- 不要做成大号徽章
- 不要用夸张渐变背景

## 12.2 `SectionBlock`

必须包含：

- 标题
- 描述
- 列表容器

规则：

- section 自身不是卡片
- 不允许把整个 section 再包一层厚重外卡片
- 每个条目卡片独立显示

## 12.3 `DailyHero`

规则：

- 第一条必须明显大于其余条目
- 但不能大到像 landing hero
- 不使用背景图
- 不使用装饰插画

## 12.4 `ArchiveDayCard`

规则：

- 这是摘要卡，不是信息瀑布卡
- 展示简洁，密度高于首页头条卡
- 推荐整卡可点击

## 13. 交互状态

必须定义以下状态：

- hover
- focus-visible
- active
- empty

### hover

- 卡片 hover 时只允许轻微边框或背景变化
- 不允许强烈位移和放大

### focus-visible

- 键盘聚焦必须有清晰外圈
- 推荐使用 `2px solid var(--accent)`

### empty

当页面或分类无数据时：

- 显示简单说明
- 提供返回首页或查看归档的入口

不要出现夸张插画空状态。

## 14. 文案规则

页面文案必须克制，直接描述信息，不写营销话术。

允许的文案风格：

- 今日 AI 资讯精选
- 最近 7 天
- 查看原文
- 返回归档
- 数据每日更新

避免的文案风格：

- 洞察未来科技趋势
- 解锁 AI 世界新篇章
- 一站式掌握行业脉搏

## 15. 大模型实现约束

为了避免大模型在实现时跑偏，必须显式限制：

1. 不要生成 marketing hero
2. 不要加入无关插画、背景 SVG、渐变球体
3. 不要把 section 包成大卡套小卡
4. 不要把首页做成博客文章列表页
5. 不要引入不必要的前端状态管理
6. 不要默认加深色主题，除非任务明确要求
7. 不要为了“现代感”牺牲信息密度
8. 不要让标题字号随 viewport 宽度缩放

## 16. 推荐实现顺序

1. 先实现全局 layout 和 token
2. 再实现 `NewsCard`
3. 再实现首页
4. 再实现归档页和单日页
5. 最后实现分类页和 about 页

## 17. 验收清单

实现完成后必须检查：

- 首页首屏是否直接出现真实资讯内容
- 页面是否更像资讯产品，而不是博客或 landing page
- 卡片层级是否清晰但不过度堆叠
- 手机端标题、摘要、元信息是否不重叠
- 桌面端是否保持良好阅读宽度
- 所有页面是否可仅依赖本地 JSON 完成静态渲染
