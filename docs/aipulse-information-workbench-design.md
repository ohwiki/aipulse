# AIpulse 信息工作台设计文档

> 对应文档：`docs/aipulse-information-workbench-requirements.md`
> 目标：在保持静态站架构不变的前提下，重构前端信息架构与页面层次。

## 1. 总体方向

AIpulse 下一阶段不再把首页当作单纯的“日报展示页”，而是采用双层结构：

- 首页：今日总览
- 列表页：高密度信息流

产品结构建议：

```text
/
|-- 今日总览
|-- 分类精选
|-- 归档入口

/latest
|-- 全部动态流
|-- 分类 / 来源 / 排序

/category/{slug}
|-- 某一赛道的专题流
|-- 来源分组 + 来源跳转

/archive
|-- 历史日报入口

/archive/{date}
|-- 单日完整日报
```

## 2. 页面角色

## 2.1 首页 `/`

角色：

- 给第一次访问和回访用户一个“今日最值得看什么”的总结
- 不承担全部内容阅读任务

结构：

1. 顶部概览
   - 日期
   - 生成时间
   - 总条数
   - 版块数
2. 收敛头条区
   - 1 主 + 3 副，最多 4 条
3. 分类导航
4. 分类精选
   - 使用去重后的剩余条目
5. 继续浏览
   - 归档或全部动态入口

设计策略：

- 减弱大 Hero
- 强化进入效率
- 控制首屏空白和重复内容

## 2.2 全部动态页 `/latest`

角色：

- 承接重度用户
- 成为“今天所有值得看内容直接刷”的核心页面

结构：

1. 页头概览
2. 分类筛选条
3. 来源筛选条
4. 排序切换
   - 最新优先
   - 评分优先
5. 高密度列表流

设计策略：

- 更像情报终端
- 信息密度高于首页
- 尽量减少大段说明文字

## 2.3 分类页 `/category/{slug}`

角色：

- 围绕单一赛道进行深入阅读

结构：

1. 页面简介
2. 分类切换
3. 来源跳转
4. 来源分组列表

设计策略：

- 同一来源集中展示，便于用户形成上下文
- 相比首页更强调连续流阅读

## 2.4 归档页 `/archive`

角色：

- 帮助用户从日期维度进入历史内容

结构：

1. 页面简介
2. 最近几期快捷跳转
3. 归档列表
4. 最新一期快速入口

## 2.5 单日页 `/archive/{date}`

角色：

- 回看某一天的完整产物

结构：

1. 日期概览
2. 版块跳转
3. 分类 section
4. 前后日期切换

## 3. 卡片设计

## 3.1 目标

卡片应从“博客卡片”收敛为“资讯卡”。

## 3.2 字段层级

一张标准资讯卡应按以下层级展示：

1. 分类标签
2. 分数
3. 信号标签
4. 中文标题
5. 英文标题（可选）
6. 来源 + 时间
7. 中文摘要
8. 推荐理由
9. 原文链接

## 3.3 信号标签

优先级：

- Featured
- Product Hunt 票数
- 官方
- 论文
- 产品榜

这些信号不替代分数，而是辅助理解排序逻辑。

## 4. 数据模型设计

前端消费的数据继续以 `data/daily/*.json` 与 `data/latest.json` 为主。

需要在前端类型层保留：

- `rankingScore`
- `votesCount`
- `featured`
- `topics`
- `rankingReason`
- `sourceType`

## 5. 内容去重策略

### 首页去重

- 头条区选出的条目，不应再在后续分类精选区重复出现

### latest 聚合去重

- `data/latest.json` 不应简单拼接多天 `daily`
- 对同 URL / 同 id 条目去重
- 保留分数更高或时间更新的一条

## 6. 稀疏态策略

### 首页稀疏态

如果头条区已覆盖当天主要内容，首页下方不再强行展示空洞 section。

### 分类页空态

不只写“暂无内容”，还应提供：

- 切换其他分类
- 去看归档

## 7. 视觉原则

- 保持浅色
- 更少装饰
- 更高密度
- 更清楚的边界
- 更少像 landing page，更多像工作台

不采用：

- 深色主风格
- 发光、渐变大背景
- 营销式大片 Hero

## 8. 实现边界

本阶段保持：

- Astro 静态构建
- GitHub Actions 产数
- JSON 回写仓库
- 静态托管平台自动构建

本阶段不引入：

- 后端运行时 API 依赖
- 数据库
- 用户态功能
