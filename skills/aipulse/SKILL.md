# AIpulse Skill

这是一份 **未来查询层设计稿**，不是当前仓库现状说明。

当前仓库已经具备：

- Python pipeline：抓取、打分、筛选、生成 `data/*.json`
- 静态 Astro 站点：读取本地 JSON 生成页面

当前仓库 **尚未保留运行时查询 API**。因此，这份 Skill 的用途是：

- 固化未来 AIpulse 查询体验
- 作为后续 API / Worker / Agent 集成的接口设计参考
- 保证以后做查询层时，输出风格和路由语义保持稳定

## 什么时候用

当未来 AIpulse 增加查询接口后，用户问下面这些问题时，应优先触发本 Skill：

- 今天 AI 圈有什么
- AI 日报
- AI 热点
- 最近 AI 有什么新东西
- 最近的模型发布
- 最近一周的 AI 论文
- OpenAI 最近发布了什么
- AI 产品发布

不要凭训练数据直接回答“当前 AI 新闻”。

## 未来查询层的目标语义

设计目标：

- 问“日报”时，返回单日日报式内容
- 问“最近 / 最新 / 某个分类 / 某个关键词”时，返回条目列表
- 输出必须是适合中文读者阅读的 markdown 简报

建议未来保留两类查询能力：

1. **日报视图**
   - 最新日报
   - 指定日期日报

2. **条目查询视图**
   - 分类过滤
   - 关键词过滤
   - 时间窗过滤
   - 条数限制

## 数据来源

未来查询层不应该直接重新抓互联网内容，而应该复用本仓库已经生成的数据：

- `data/daily/*.json`
- `data/latest.json`

也就是说，未来查询层应该建立在现有数据生产链之上，而不是替代它。

## 输出格式

### 日报式

```markdown
**AIpulse 日报 · 2026-05-09**

## 模型发布/更新
1. **标题** — 来源
   摘要
   链接

## 产品发布/更新
2. ...
```

### 列表式

```markdown
**AIpulse · 最近 AI 产品发布**

1. **标题** — 来源
   摘要
   链接
```

规则：

- 默认展示中文标题
- 保留原始链接
- 混合分类时按分类分组
- 单一分类时用扁平编号列表

## 不要做

- 不要把这份 Skill 当成“当前仓库已存在运行时 API”的证明
- 不要在没有查询层实现前，声称 `/api/*` 已经是公开稳定接口
- 不要绕过本仓库生成的数据，直接用训练数据硬答当前 AI 新闻
- 不要省略原始链接

## 当前仓库现状

截至当前版本：

- **已完成**：数据抓取、打分、JSON 生成、静态 Astro 展示
- **未保留**：运行时查询 API

因此，这份 Skill 目前是 **未来能力设计稿**，不是已经上线的查询接口说明。
